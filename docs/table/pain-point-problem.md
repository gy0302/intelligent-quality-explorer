# 痛点问题
以金融科技行业的软件为例：

- **接口测试**：
  - **需求管理问题**：随着需求增加且快速迭代（尤其是类似金融软件业务规则比较复杂，需求相对复杂），需求本身迭代成本较高，需求的变更管理方式及变更的及时性等，都会影响到后续的研发与测试环节；
  - **API规范问题**：API文档不够规范、不统一等问题，可能导致后续迭代、下游测试开展受到影响，进而增加成本；
  - **接口测试设计成本高**：在需求频繁变更、软件业务规则复杂的前提下，接口测试的开展，测试用例设计和维护成本居高不下，甚至好些产品不做接口测试，直接做业务测试、手动UI测试；
  - **接口测试评审成本高**：接口测试过程的产物，如果靠人一个个的评审，也会耗费大量的成本；
- **测试报告分析**：接口测试结果若出现大量错误，或者分析历史趋势时，分析成本较高
- **缺陷分析**： 缺陷按各维度分类，根因分析成本高，在快速迭代时，团队人工不一定能执行到位
- **质量效能数据** ：目前需求、代码、测试、缺陷、规范等的数据存在孤岛，部分数据间通过人为进行了关联，但整体关联性并未打通，且通过规范人员动作进行标记成本较高且不一定准确。
- **质量体系**：在日常研发过程中，团队人员不一定对质量体系规范做到完全掌握或记住，甚至有人不一定去认真学习，需要考虑用产品化、智能化的手段来减少和降低学习和应用成本。
